# 까치녹음기 계획 & 진행 상황

## 확정된 결정
- 대상: 여자친구 맥(Apple Silicon), 비개발자. AI 요약 없음. 화자 구분 필수. 한국어·영어·한영 혼합.
- 전사 엔진: **Qwen3-ASR 1.7B 8bit (MLX)** — 2026-10-02 벤치마크로 확정 (아래 참고)
- 화자 구분: **Nemotron 3 Diarization (MLX)** — Hugging Face 토큰 불필요, 최대 8명. pyannote는 실제 녹음에서 품질이 부족할 때만 예비로 검토 (토큰 필요)

화자 구분 Nemotron 3 (MLX): 같은 10분 녹음 **0.7초**, 화자 2명 정확히 구분 (합성 음성 기준).

→ 1시간 녹음 ≈ 전사 2분 안팎 (M5 기준, 여자친구 맥은 더 빠를 것). 단어 정렬 시간은 Step 1에서 측정.

Step 1 파이프라인 전체 (10분 46초, M5): 변환 0.1s + 전사 25.9s + 단어 정렬 5.8s = **31.7s (실시간 20배)**, 모델 로딩 3.5s 별도.
Step 2 파이프라인 전체 (10분 46초): 화자구분 0.6s + 전사 19.8s + 정렬 12.4s = **32.9s**. 정답 43발언(화자1 22 / 화자2 21)과 정확히 일치.
3인 대화(50초, 한국어 남·여 + 영어 여): 3명 구분 및 발언 경계 전부 정확.
※ 화자 수를 실제보다 적게 지정하면 말한 시간이 적은 사람이 다른 사람에게 합쳐진다 → 화면에서 "모르면 자동" 안내.
※ 메모리 16GB 맥에서 스왑이 많이 차 있으면 수 배 느려질 수 있음 (한 번 관찰됨).

Step 2.5 혼합 모드 (10분 46초): 언어감지 1.5s 포함 **합계 51~58s (실시간 11~13배)**. 43발언 화자·언어 전부 정답, 번역 현상 없음.
→ 2시간 강의 ≈ 10분 안팎 (M5, 스왑 많은 상태 기준). 배치 16은 메모리 부족으로 오히려 느림(66.7s) → 8 유지.

Step 3 실서버 확인: 업로드 → 진행률(파일 읽기→화자 구분→언어 확인→받아쓰기→완료) → 결과 조회 정상.
처리 중 `kill -9` 후 재시작 → "앱이 꺼져서 멈췄어요" 실패 표시 → 다시 시도로 완료 (10분 녹음 41.7초).
- caffeinate 를 그냥 띄우면 앱이 강제 종료될 때 고아로 남아 맥이 계속 깨어 있음 → `-w <pid>` 로 해결.

Step 5 확인 (테스트 음성을 가짜 마이크로 넣어 실제 흐름 재현): 녹음 39초 → 일시정지 구간 제외하고 저장 → 받아쓰기 완료, 재생바 길이 정상(39.1초).
녹음 중 페이지 이탈 → 45초 뒤 '끊김' 표시 + caffeinate 해제 → '여기까지 받아쓰기'로 저장된 10초 전사.
- 최대 손실은 마지막 조각(10초 이하).
- **사파리(audio/mp4 조각) 이어붙이기는 아직 실기기 미확인** → Step 9에서 여자친구 맥 사파리로 확인.

Step 6 확인: 화자 이름/제목/화자 바꾸기/새 화자/글자 고치기/문단 삭제/재생 강조 모두 화면·서버 반영 확인.
'영어로 다시 받아쓰기' 실모델: "보스 아 커먼 인 파이썬 컬렉션스…" → "…Python Collections dot deque uses a doubly linked list of blocks."
- `<dialog>` 의 close 이벤트는 창이 가려져 있으면 안 올 수 있음 → 확인 버튼 클릭을 직접 받도록 변경.

Step 7 확인: 'deque' 검색 → 3개 녹음 4건, 결과 눌러 해당 문단(노란 표시)·재생 위치 0:21 이동. 전체 복사 → 시스템 클립보드 내용 확인.
- 클립보드 API 는 내용을 서버에서 받아오는 동안 '방금 누름' 상태가 끊겨 거부됨(사파리는 특히 엄격). 미리보기 브라우저는 권한 자체가 denied.
  → 화면 데이터로 즉시 만들고 execCommand('copy') 먼저, 안 되면 클립보드 API.

Step 8 확인 (새 폴더에 clone 해서 설치 재현): 모델 받기 → **오프라인 시험 받아쓰기 성공** → 앱 생성·실행 → 오프라인 받아쓰기(3화자, 9초) → 화면 '끄기'로 서버·앱 함께 종료 → 재실행 후 ⌘Q 로 정상 종료(caffeinate 정리까지).
- **셸 스크립트 .app 은 스크립트가 끝나면 macOS 가 띄운 서버까지 종료시킴** (nohup, 새 세션 모두 실패) → 계속 살아 있는 Swift Cocoa 실행기로 교체.
- Pillow 는 ZWJ 이모지(🐦‍⬛)를 합치지 못해 깨짐 → 아이콘은 AppKit(Swift)로 그림.

### Step 2.5에서 알아낸 것
- **Qwen 자동 언어 감지는 구간 첫머리 언어로 구간 전체를 정한다.** 영어 질문 + 한국어 답변이 한 구간에 들어가면
  한국어 답변을 **영어로 번역해서** 적었다. → 전용 언어 감지 모델로 먼저 나누고, 언어를 고정해서 전사.
- **화자 턴 하나씩 짧게 잘라 전사하면 맥락이 없어져 인식이 크게 나빠진다** (짧은 질문이 엉뚱한 문장으로 나옴).
  → 같은 언어 안에서는 30초까지 묶어 맥락 유지.
- mlx-audio 0.5.7 `lid.load()`는 ECAPA 체크포인트를 못 읽음 (`ModelConfig.from_dict` 없음) → 직접 조립.
- 한국식 발음으로 읽은 영어 문장(합성 음성)은 언어 감지가 ko로 판정해 한글로 적힌다. 실제 녹음으로 확인 필요.

### 알아낸 것 (구현 시 주의)
- `mlx-audio`의 Qwen3-ASR `generate(language=None)`은 **첫 청크의 언어만 파싱**한다.
  배치 모드에선 이후 청크 텍스트에 `language Korean<asr_text>` 접두어가 그대로 남는다.
  → 우리가 직접 구간을 나눠 넣고, 구간마다 접두어를 파싱해서 언어를 기록해야 함 (혼합 모드의 핵심).
- 한국어 문장 속 영어 용어는 발음에 따라 한글로 적히기도 함 (예: collision → 컬리전).
  → `hotwords`(용어 힌트)는 효과가 약함 (링크들→링크드 정도). 합성 음성이 영어를 한국식으로 읽은 탓일 수 있어 실제 녹음으로 재확인.
  → 부족하면 Step 2.5/6에서 **용어 치환 사전**(예: 컬리전 → collision) 추가 검토.
- 30초 구간 안에 한·영이 섞이면 구간 언어 표시가 부정확함 (예: 대부분 한국어인데 EN). → Step 2.5에서 화자 전환·침묵 기준으로 더 잘게 나눠 해결.
- `_generate_chunks_batched`(mlx-audio 내부 함수)를 직접 사용 → `mlx-audio==0.5.7`로 고정. 업그레이드 시 확인 필요.
- 원본 `generate()`의 `max_tokens=8192`는 **파일 전체 합계**라 긴 강의가 잘림 → 우리는 배치마다 구간당 448토큰으로 따로 줌.
- `mlx-community/whisper-large-v3-turbo`는 mlx-audio로는 안 열림(processor 없음). 비교용으로만 mlx-whisper 사용.
